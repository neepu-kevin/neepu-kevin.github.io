Codex Skill 与 MCP

Posted on 2026-10-12 In AI Agent Views: Word count in article: 1.2k Reading time ≈ 4 mins.
介绍 Codex Skill 与 MCP 的区别、配置方式和组合使用方法。

前言

在使用 Codex 或其他 AI Agent 时，我们经常会遇到两个概念：Skill 和 MCP。

它们都能扩展 Agent 的能力，但负责的工作并不相同：

  • Skill 负责告诉 Agent 应该如何完成某类任务。
  • MCP 负责向 Agent 提供外部工具、实时数据和操作能力。

本文将介绍二者的区别，并通过简单示例说明如何组合使用它们。

一、什么是 Skill

Skill 可以理解为一套可重复使用的工作说明。

它通常是一个包含 SKILL.md 的文件夹，也可以包含脚本、参考资料和模板。

二、什么是 MCP

MCP 的全称是 Model Context Protocol。

它用于把外部系统提供的工具和数据连接给 Agent，例如：

  • 搜索文档；
  • 查询数据库；
  • 读取 GitHub 仓库；
  • 操作项目管理系统；
  • 调用内部业务接口；
  • 获取实时数据。

与 Skill 不同，MCP 不只是说明文字，它通常对应一个正在运行的服务。

三、Skill 和 MCP 的区别

对比项目 Skill MCP
主要作用 描述工作流程 提供工具和数据
是否需要服务端 不一定需要 通常需要
是否可以包含脚本 可以 由 MCP 服务实现
是否能访问实时数据 通常不能 可以
是否能执行外部操作 依赖已有工具 可以提供受控操作
典型文件 SKILL.md MCP 服务配置
适合场景 编写规范、检查流程、固定模板 数据查询、外部接口、系统操作

简单来说：

MCP 解决“Agent 能做什么”，Skill 解决“Agent 应该怎么做”。

六、什么时候只需要 Skill

以下情况通常只需要 Skill：

  • 统一博客文章格式；
  • 规定代码审查流程；
  • 使用固定的报告模板；
  • 规定文件命名方式；
  • 规范测试和交付步骤；
  • 处理本地已有文件。

例如 Hexo 文章编写规范，通常不需要专门开发 MCP。

七、什么时候需要 MCP

以下情况更适合使用 MCP：

  • 获取实时信息；
  • 查询远程数据库；
  • 访问 GitHub、Jira 等外部系统；
  • 操作企业内部接口；
  • 读取需要认证的数据；
  • 执行受权限控制的外部操作。

如果任务需要登录、鉴权、实时数据或者外部操作，只写一个 Skill 通常不够。

3. MCP 能不能代替 Skill

不能完全代替。

MCP 可以提供工具，但不一定知道你的业务流程。例如 MCP 提供了“搜索”和“读取”工具，却不会自动规定：

  • 应该先搜索什么；
  • 如何选择结果；
  • 是否必须读取全文；
  • 最终输出什么格式。

这些工作更适合由 Skill 规定。

总结

Skill 和 MCP 分别处于不同层次：

对于简单、固定的本地工作流，可以先编写 Skill。

当任务需要实时数据、远程系统或外部操作时，再接入 MCP。

二者结合后，可以让 Agent 不仅拥有工具，还能稳定地按照正确流程使用这些工具。
